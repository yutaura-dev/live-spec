# Documentation

このディレクトリには live-spec の設計文書を、**更新頻度（Stability）ごとに分けて**置いている。

## 読む順序

1. **[charter.md](charter.md) 🪨**: 最初に読む。存在意義・スコープ・撤退条件
2. **[plan.md](plan.md) 🌀**: 次に読む。現在のフェーズと今後のマイルストーン
3. **[architecture.md](architecture.md) 🌊**: 実装に関わる人が読む。技術スタックと設計判断
4. **[research/](research/)**: 既存ツールの調査。設計判断の根拠をたどりたいときに読む
5. **[decisions/](decisions/)**: 過去の重要な決定の経緯をたどりたいときに読む

## Stability の見方

| Stability | 意味 | 変更時の重み |
|-----------|------|--------------|
| 🪨 stable | プロジェクトのアイデンティティ。原則として変えない | 重い（ADR 必須） |
| 🌀 evolving | 計画・ロードマップ。フェーズの進行に合わせて更新する | 中（更新するタイミングを決めておく） |
| 🌊 living | 実装・運用の現状。日々書き換える | 軽い（自由に更新してよい） |

## 文書の更新ルール

- **🪨 stable** の文書を変更するときは、必ず `decisions/` に ADR を書く
- **🌀 evolving** の文書は、フェーズの完了時か計画の見直し時に更新する
- **🌊 living** の文書は、実装に合わせて自由に更新する
- **research/** の調査はその時点のスナップショットなので、後から書き換えない。調べ直したら新しいファイルを足す
- すべての文書の冒頭に **最終更新日** と **直近の変更 ADR** を書く
